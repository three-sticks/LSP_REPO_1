# Question 1 – CRC Card Explanation

Library collaborates with Book because its CRC responsibilities (add and find books, coordinate borrowing/returning) require it to send messages to Book objects, such as `borrowBook()`, `returnBook()`, and `isAvailable()`, rather than changing availability itself. Book does not collaborate with Library because its responsibilities (store book information, maintain availability, validate borrowing/returning) concern only its own state, so it needs no knowledge of any collection and can even be borrowed as a standalone object. Library enforces the three-book borrowing limit because the limit is a rule about the whole set of borrowed books, a count that no single Book can see, which matches Library's "enforce borrowing limit" responsibility. By checking the count first and only then delegating the state change to Book, Library guarantees that a rejected borrow leaves every book and the borrowed count unchanged.
